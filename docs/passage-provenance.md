# Происхождение фрагментов и фиксация сверки

## Назначение и границы

Документ описывает четыре необязательных поля PassageRecord, добавленные
в коммите 74bb345. Поля предназначены для прозрачного учёта получения
текста, подготовки записи и сверки транскрипции.

Они не доказывают исторического влияния, не устанавливают смысловую
достоверность интерпретации и не разрешают публикацию или передачу текста
внешнему провайдеру.

На этом этапе поля поддерживаются моделью импорта и JSON Schema.
Их передача через поиск, API и генератор и отображение в интерфейсе
не входят в данный этап.

## Поля

| Поле | Назначение | Значение при отсутствии поля |
| --- | --- | --- |
| acquisition_method | Как текст получен для проекта | not_recorded |
| prepared_by | Кто подготовил запись для проекта | not_recorded |
| verification_status | Зафиксирована ли сверка транскрипции с источником | not_recorded |
| verification_reference | Издание и место, с которыми сверяли текст | None |

### acquisition_method

- `not_recorded` — способ получения не зафиксирован.
- `direct_transcription` — текст непосредственно переписан из источника.
- `user_excerpt` — текст поступил как пользовательская выписка.
- `ocr` — текст получен посредством оптического распознавания.

Способ получения не является оценкой точности. Например, OCR не означает
автоматически ошибочный текст, а непосредственная транскрипция не означает,
что проведена отдельная сверка.

Поле содержит одно значение и не описывает всю историю обработки.
Если история сложнее, не следует выдавать одну категорию за её полное
представление. Расширение модели обсуждается отдельно.

### prepared_by

- `not_recorded` — подготовивший запись не указан.
- `project_author` — запись подготовил автор проекта.
- `ai` — запись подготовлена AI.
- `other_editor` — запись подготовил другой редактор.

Это не автор произведения и не обязательно автор опубликованного перевода.
Поле не заменяет `is_machine_generated`. Смешанное участие человека и AI
не следует автоматически сводить к утверждению о полностью человеческом
или полностью машинном происхождении.

### verification_status

- `not_recorded` — сведений о сверке нет. Это не утверждение, что её никогда
  не проводили.
- `not_checked` — явно зафиксировано, что сверка не проводилась.
- `checked_against_source` — зафиксировано проведение сверки с указанным
  источником.

При `checked_against_source` требуется непустое `verification_reference`.
Валидатор проверяет наличие ссылки, но не факт проведения сверки,
точность транскрипции или доступность источника.

`review_status=reviewed`, `is_verbatim=true` и наличие библиографической
ссылки сами по себе не присваивают статус сверки.

### verification_reference

Текстовое описание источника и конкретного места, использованных
для сверки. Для новой записи указывайте достаточные сведения об издании
и локаторе: том, главу или параграф, печатную страницу. Номер листа PDF
указывайте отдельно и обозначайте способ нумерации, если он используется.

Наличие ссылки само по себе не меняет `verification_status`.
`None` в Python и `null` в JSON означают отсутствие значения.

## Совместимость и пустые значения

Существующие CSV не требуется дополнять новыми столбцами только ради
загрузки: модель использует значения по умолчанию.

При вводе через модель импорта пустые или состоящие из пробелов ячейки
трёх категориальных полей нормализуются в `not_recorded`, а пустая
`verification_reference` — в `None`.

Для JSON, проверяемого непосредственно по JSON Schema, передавайте
допустимые значения либо опускайте необязательные поля. Schema не выполняет
CSV-нормализацию Python-модели и не обязана заполнять данные значениями
из аннотации `default`.

## Синтетические примеры

Ниже показаны только четыре дополнительных поля, а не полные записи.
Примеры не относятся к реальным изданиям или проверенным цитатам.

### Пользовательская выписка без сведений об отдельной сверке

```json
{
  "acquisition_method": "user_excerpt",
  "prepared_by": "project_author",
  "verification_status": "not_recorded",
  "verification_reference": null
}
```

Такая запись допустима для рабочей загрузки. Сам по себе этот статус
не является запретом на исследовательское использование выписки.

### OCR, для которого сверка ещё не проводилась

```json
{
  "acquisition_method": "ocr",
  "prepared_by": "not_recorded",
  "verification_status": "not_checked",
  "verification_reference": null
}
```

Из способа получения OCR не выводится личность подготовившего запись
или значение существующего признака `is_machine_generated`.

### Транскрипция с зафиксированной сверкой

```json
{
  "acquisition_method": "direct_transcription",
  "prepared_by": "project_author",
  "verification_status": "checked_against_source",
  "verification_reference": "Синтетическое издание, том 1, § 2, печатная с. 7; лист PDF 9, нумерация с 1"
}
```

Этот пример показывает заполнение полей, а не свидетельствует
о существовании или проверке названного источника.

## Исследовательские правила проекта

1. Рабочие выписки пользователя принимаются с обозначением их статуса.
   Сплошная повторная сверка не является условием их использования.
2. Конкретное место проверяется, если точность влияет на смысл,
   аргумент или атрибуцию. Расширение проверки предварительно согласуется.
3. Первичный текст, пользовательский комментарий, редакторское изложение
   и интерпретация AI не должны выдаваться друг за друга. Эти четыре поля
   дополняют существующую маркировку, но ещё не представляют полноценную
   модель авторства и привязки комментариев.
4. Текстуальное сходство и общая тема не доказывают исторического влияния.
5. Проверка транскрипции, научное одобрение и права использования —
   отдельные вопросы.
6. Проверки примеров и метаданных не требуют живых вызовов моделей,
   эмбеддингов, индексации или подключения к базе. Платные вызовы
   для такой проверки не допускаются.

## Что этот документ не меняет

Документ не изменяет корпус, существующие ID и тексты, оценки прошлых
экспериментов, настройки провайдеров, Neo4j, CI или Production-инструкцию.
Он не расширяет автоматически разрешения на распространение материалов.
